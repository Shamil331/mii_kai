# Сравнительная таблица: Cloud-агенты vs IDE/CLI AI-агенты

**Контекст оценки:** разработка веб-MVP NutriDay (FoodTech): меню наборов, корзина/заказ, доставка.  
**Шкала:** 1 — слабо / непригодно; 5 — отлично / оптимально для задачи.  
**Оценки** отражают типичные условия студенческого/учебного проекта (2025–2026): доступ к локальному репозиторию, Next.js + TypeScript, ограниченный бюджет, работа с персональными данными заказа.

### Пояснения к оценкам (сноски)

1. **Bolt.new / Lovable:** контекст ограничен сессией в браузере и загруженными/сгенерированными файлами; нет устойчивого доступа к полному локальному git-репозиторию, истории коммитов и соседним ДЗ-папкам (`hw2/`, `hw3/`).
2. **Replit Agent:** видит файлы внутри Replit-проекта; при переносе на GitHub/локальную машину контекст разрывается; для NutriDay с целевым репо `Shamil331/mii_kai` это лишний слой синхронизации.
3. **Cursor:** индексирует открытый workspace, правила проекта, соседние файлы; подходит для итеративной доработки корзины, API заказа и страниц меню в одном репозитории.
4. **GitHub Copilot:** хорошо видит открытые файлы и соседний код в IDE; слабее Cursor в многошаговых агентных правках по всему проекту без явного чата/агента.
5. **Claude Code:** CLI-агент с доступом к файловой системе и командам в каталоге проекта; сильный контекст при работе из корня репозитория.
6. **Bolt / Lovable:** быстрый «с нуля» UI и каркас приложения за минуты — удобно для прототипа лендинга, но не для аккуратной эволюции MVP.
7. **Replit Agent:** генерация быстрая внутри облачной среды; задержки связаны с сетью и запуском среды.
8. **Cursor:** генерация в чате/агенте быстрая; полные многофайловые правки чуть медленнее однострочных автодополнений.
9. **Copilot:** мгновенные inline-suggestions; агентный режим (если доступен) сопоставим по скорости с Cursor для локальных правок.
10. **Claude Code:** качество высокое, но цикл «промпт → дифф → проверка» в терминале обычно медленнее IDE-чата с превью.
11. **Bolt / Lovable:** код «демо-качества»: часто жёстко связанные компоненты, слабая типизация, мало внимания к граничным случаям корзины (кол-во = 0, дата доставки ≥+2 дня).
12. **Replit:** приемлемый каркас; качество зависит от промпта; риск «облачного» стиля без выровненного под Next.js App Router + Tailwind стека ДЗ.
13. **Cursor:** при хороших промптах и правилах проекта даёт согласованный TypeScript, компоненты React и структуру папок под MVP.
14. **Copilot:** отличное автодополнение; для целостной фичи «оформление заказа» чаще нужны несколько ручных итераций.
15. **Claude Code:** силён в многофайловых рефакторингах и проверке логики (итог корзины, валидация адреса).
16. **Bolt / Lovable:** бесплатный/ограниченный tier достаточен для прототипа; платная подписка для серьёзного объёма генераций.
17. **Replit:** кроме AI часто нужна оплата compute/хостинга среды — для учебного MVP это избыточно.
18. **Cursor:** студенческий/Pro-тариф; предсказуемая месячная плата при интенсивной разработке.
19. **Copilot:** относительно доступен через студенческие/индивидуальные планы; хорошо стыкуется с GitHub.
20. **Claude Code:** стоимость привязана к API/подписке Anthropic; при активном агентном цикле расход выше.
21. **Cloud-агенты:** код, промпты и фрагменты данных заказа уходят на сторонние серверы; для FoodTech с адресом доставки и оплатой это повышает риск утечки PII при неосторожных промптах.
22. **Cursor / Claude Code:** код остаётся локально; отправка в модель — по политике провайдера; проще контролировать `.env`, ключи оплаты и не вставлять реальные ПДн в чат.
23. **Copilot:** код обрабатывается по политикам GitHub/Microsoft; для приватных репо нужна проверка настроек телеметрии и enterprise-ограничений.
24. **Bolt / Lovable:** отдельный облачный цикл; экспорт в GitHub возможен, но ежедневный workflow (lint, локальный `next dev`, ДЗ1–ДЗ3 в одной папке) неудобен.
25. **Replit:** удобно «писать и сразу запускать» в облаке; хуже стыкуется с локальным Windows-окружением и структурой `hw1/hw2/hw3`.
26. **Cursor:** нативный IDE-workflow: открыл `дз МИИ` → чат/агент → git → GitHub; оптимально для курса МИИ.
27. **Copilot:** отличная интеграция в VS Code/JetBrains; слабее как «агент всего репозитория» по сравнению с Cursor Agent.
28. **Claude Code:** хорошо встраивается в терминальный git/CI-цикл; менее нагляден для UI-итераций Next.js без IDE-превью.

## Краткая характеристика классов инструментов

| Класс | Представители | Сильная сторона | Слабая сторона для NutriDay |
|---|---|---|---|
| **Cloud AI-агенты** | Bolt.new, Lovable, Replit Agent | Быстрый прототип UI «с нуля» в браузере | Слабый долгосрочный контекст репо, хуже безопасность PII, разрыв с локальным стеком |
| **IDE/CLI AI-агенты** | Cursor, GitHub Copilot, Claude Code | Работа в реальном проекте, контроль кода и секретов | Нужна локальная среда; скорость «вау-прототипа» ниже облачных билдеров |

**Вывод таблицы:** для разработки NutriDay (меню → корзина → заказ с доставкой) в структуре курса с локальными файлами и GitHub предпочтительны **IDE/CLI-агенты**; среди них оптимален **Cursor**. Cloud-агенты целесообразно использовать лишь на этапе раннего визуального прототипа, не для основной кодовой базы MVP.
