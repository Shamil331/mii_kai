# ДЗ1. Сравнительный анализ Cloud и IDE/CLI AI-агентов для разработки NutriDay

**Дисциплина / курс:** МИИ  
**Продукт:** NutriDay — веб-MVP заказа готовых наборов здорового питания  
**Целевой репозиторий:** `Shamil331/mii_kai` (папки `hw1/`, `hw2/`, `hw3/`)  
**Приложение к отчёту:** `comparison_table.md`, каталог `screenshots/`

## Шаг 1. Требования к проекту и критерии выбора инструмента

### 1.1. Суть проекта NutriDay

NutriDay — FoodTech-сервис для аудитории 25–45 лет с ограниченным бюджетом: пользователь выбирает тип рациона / набор на день или неделю, формирует корзину, указывает дату доставки (не раньше чем через +2 дня), адрес и оплачивает заказ. Вне MVP: сложная кастомизация блюд, собственная логистика, AI-рекомендации.

Планируемый стек (для последующих этапов курса): **Next.js (App Router) + TypeScript + Tailwind CSS**.

### 1.2. Сложность и характер работ

| Аспект | Оценка для NutriDay |
|---|---|
| Сложность | Средняя: несколько связанных экранов (меню, корзина, оформление), клиентское состояние, валидация даты/адреса, подготовка к оплате |
| Объём кода | Небольшой MVP, но с итерациями и рефакторингом под единый стиль |
| Локальные файлы | Обязательны: работа в каталоге `дз МИИ`, отдельные ДЗ, git, выгрузка на GitHub |
| Безопасность | Высокая чувствительность: адрес доставки, платёжный контур, `.env` с ключами — нельзя свободно отправлять в публичные облачные песочницы |
| Бюджет | Студенческий / ограниченный: предпочтительны предсказуемые подписки IDE, без обязательной оплаты cloud-compute |

### 1.3. Выведенные требования к AI-агенту

1. **Доступ к полному контексту** локального репозитория и соседних файлов.  
2. **Контролируемая генерация** компонентов React/Next с возможностью правок «на месте».  
3. **Минимизация риска утечки** персональных и секретных данных.  
4. **Встраивание в учебный workflow:** IDE → git → GitHub, без обязательного переноса проекта между облачными средами.  
5. **Приемлемая стоимость** при регулярной генерации кода в течение семестра.

Эти требования определяют приоритет **IDE/CLI-агентов** над чисто облачными билдерами приложений.

## Шаг 2. Анализ инструментов (по таблице сравнения)

Полная оценка приведена в файле `comparison_table.md`. Ниже — сжатый разбор по классам.

### 2.1. Cloud-агенты (Bolt.new, Lovable, Replit Agent)

**Сильные стороны:** скорость получения визуального прототипа «с нуля»; низкий порог входа (браузер); удобны для демонстрации идеи меню и корзины за один сеанс.

**Слабые стороны для NutriDay:**

- ограниченный и нестабильный доступ к долгосрочному контексту учебного репозитория;
- код часто «демо-уровня» (слабая типизация, хрупкая логика итога корзины);
- данные и промпты обрабатываются на стороне облачного сервиса — риск для сценариев с адресом и оплатой;
- неудобная стыковка с локальным Next.js-проектом и структурой `hw1/hw2/hw3`.

По сумме критериев все три cloud-инструмента получили средний балл **2,8 / 5**.

### 2.2. IDE/CLI-агенты (Cursor, GitHub Copilot, Claude Code)

**Сильные стороны:** работа непосредственно в файлах проекта; возможность ссылаться на существующие компоненты; контроль `.gitignore` и секретов; естественный git-workflow.

**Различия:**

- **Cursor** — максимальный балл за контекст проекта и интеграцию в workflow (средний **4,3**).  
- **GitHub Copilot** — отличная скорость inline-подсказок (**4,0**), но слабее как «агент всего MVP».  
- **Claude Code** — высокое качество многофайловых правок (**3,8**), но CLI-цикл менее удобен для быстрых UI-итераций и может быть дороже по API.

### 2.3. Сопоставление с требованиями шага 1

| Требование NutriDay | Cloud | IDE/CLI |
|---|---|---|
| Локальные файлы и git | Слабо | Хорошо |
| Качество TypeScript/React MVP | Средне | Хорошо / отлично |
| Безопасность PII и секретов | Хуже | Лучше |
| Бюджет студента | Зависит от тарифа + часто compute | Предсказуемее |
| Скорость «вау-прототипа» | Лучше | Достаточно |

**Вывод шага 2:** для основной разработки NutriDay следует выбирать IDE/CLI-агент; cloud — только как опциональный инструмент раннего прототипирования UI.

## Шаг 3. Выбор оптимального инструмента

### 3.1. Выбор: Cursor

**Cursor** выбран как оптимальный AI-агент для разработки NutriDay по следующим причинам:

1. **Контекст:** индексирует workspace `дз МИИ`, видит связанные файлы меню/корзины/заказа, позволяет опираться на `SHARED_BRIEF.md`.  
2. **Качество под стек курса:** хорошо генерирует и правит Next.js App Router, TypeScript и Tailwind.  
3. **Workflow:** установка → открытие папки → Chat/Agent → локальный запуск → commit/push в `Shamil331/mii_kai`.  
4. **Безопасность:** исходники остаются локально; в промпты не включаются реальные адреса и ключи оплаты.  
5. **Соответствие курсу:** в shared brief для последующих ДЗ уже зафиксирован Cursor как AI-агент разработки.

### 3.2. Альтернативы и почему они не выбраны как основные

| Альтернатива | Почему не основной выбор |
|---|---|
| **GitHub Copilot** | Силён в автодополнении, но уступает Cursor в управляемой многошаговой сборке фич MVP (корзина + валидация доставки) одним агентным циклом. |
| **Claude Code** | Высокое качество кода в CLI; менее нагляден для UI Next.js; стоимость API при активной работе может быть выше. |
| **Bolt.new / Lovable** | Быстрый прототип, но слабый контроль локального репозитория и безопасности; экспорт усложняет учебный git-процесс. |
| **Replit Agent** | Удобная облачная среда, но лишняя зависимость от Replit compute и рассинхрон с локальной структурой ДЗ. |

**Итог:** Cursor — основной инструмент; Copilot допустим как дополнение для inline-подсказок; cloud-агенты — только для разового UI-sketch.

## Шаг 4. Описание настройки Cursor

Скриншоты процесса размещаются в каталоге `screenshots/` (см. `screenshots/README.md`). На этапе сдачи ДЗ1 допустимы плейсхолдеры с подписями.

### 4.1. Установка

1. Скачать Cursor с официального сайта и установить на Windows.  
2. Войти в аккаунт / активировать доступ к моделям (студенческий или Pro — по наличию).  
3. При необходимости включить автообновления IDE.

### 4.2. Открытие проекта

1. `File → Open Folder` → указать `C:\Users\user\Desktop\дз МИИ`.  
2. Убедиться, что в боковой панели видны `SHARED_BRIEF.md`, `hw1/`, (позже) `hw2/`, `hw3/`.  
3. Открыть Chat / Agent и приложить краткий контекст: цель NutriDay, стек Next.js + TS + Tailwind, ограничения MVP.

### 4.3. Рекомендуемые настройки для учебного проекта

- не вставлять в чат содержимое `.env`, номера карт, реальные ФИО/адреса;
- при работе с агентом явно указывать путь (`hw2/...` и т.д.), чтобы не смешивать ДЗ;
- использовать правила проекта (`.cursor/rules` / project rules), если они появятся на следующих этапах.

### 4.4. Опционально: MCP

MCP (Model Context Protocol) в Cursor позволяет подключать внешние инструменты (документация, браузер, трекеры задач). Для ДЗ1 **не обязателен**: достаточно встроенного чата/агента и доступа к файлам workspace. MCP имеет смысл позже, если понадобится, например, подтягивать актуальную документацию Next.js без копирования больших фрагментов вручную.

### 4.5. Скриншоты

Ожидаемые кадры: окно настроек Cursor; чат с генерацией компонента корзины; открытый workspace NutriDay. Файлы: `screenshots/` (см. README в каталоге).

## Шаг 5. Практический пример: генерация компонента итога корзины

### 5.1. Цель примера

Сгенерировать простой React/Next-компонент (или функцию) **сводки корзины** NutriDay: список позиций набора, изменение количества, подсчёт итога. Это ядро Must-have №2 из brief.

### 5.2. Использованные промпты (итерации)

**Промпт 1 (базовая генерация):**

> Создай клиентский React-компонент `CartSummary` для NutriDay на TypeScript.  
> Пропсы: массив `{ id, title, priceRub, qty }`.  
> Покажи список позиций, кнопки −/+ для количества, сумму в рублях.  
> Стиль: Tailwind, без внешних UI-библиотек. Не добавляй оплату.

**Результат:** получен каркас с `map` по позициям и суммой `priceRub * qty`. Частая проблема первой версии — отсутствие защиты от `qty < 1` и неудобный подъём состояния наверх.

**Промпт 2 (уточнение):**

> Доработай: минимальное количество = 1; добавь кнопку «Удалить»; сумму считай через `useMemo`; вынеси тип `CartItem` в отдельный export. Компонент должен быть готов к App Router (`'use client'`).

**Результат:** код стал ближе к продакшен-MVP; появились явные типы и клиентская директива.

**Промпт 3 (связь с заказом):**

> Добавь под компонентом блок «К оформлению»: disabled, если корзина пуста; текст-подсказку, что дата доставки должна быть ≥ сегодня+2 дня (только UI-предупреждение, без полной формы заказа).

**Результат:** простая связка с Must-have №3 без выхода за рамки MVP.

### 5.3. Трудности и как решались

| Трудность | Как проявилась | Решение |
|---|---|---|
| Смешение server/client в Next.js | Агент забывал `'use client'` при `useState` | Явно указать App Router и хуки в промпте |
| «Раздувание» scope | Предложения добавить оплату/логистику | В промпте: «вне MVP не делать» |
| Несогласованные имена полей | `price` vs `priceRub` | Зафиксировать типы в brief/промпте |
| Риск утечки данных | Желание вставить «пример адреса» из жизни | Использовать только вымышленные данные |

### 5.4. Наблюдение по классу агентов

Тот же сценарий в cloud-билдере дал бы быстрее «красивую страницу», но хуже контроль типов, git-диффа и повторного использования компонента в реальном Next.js-проекте. Cursor выгоднее именно на **итерациях 2–3**, когда важна точечная доработка.

## Шаг 6. Выводы и рекомендации

### 6.1. Выводы

1. Для NutriDay критичны **локальный контекст**, **безопасность данных заказа** и **совместимость с git/GitHub** — по этим осям IDE/CLI-агенты стабильно превосходят cloud-билдеры.  
2. Cloud-инструменты (Bolt.new, Lovable, Replit Agent) полезны для **быстрого визуального прототипа**, но слабы как основной контур разработки учебного MVP.  
3. Среди IDE/CLI лучший баланс для курса показал **Cursor** (средний балл 4,3 в таблице).  
4. Практическая генерация `CartSummary` подтвердила: качество растёт за счёт **коротких итеративных промптов** с явными ограничениями MVP.  
5. Стоимость и безопасность управляемы, если не передавать в модель секреты и реальные ПДн и работать в локальном репозитории.

### 6.2. Рекомендации

- **Основной инструмент разработки NutriDay:** Cursor.  
- **Дополнительно:** GitHub Copilot — для ускорения рутинного автодополнения; Claude Code — для сложных CLI-рефакторингов по желанию.  
- **Cloud-агенты:** только этап idea → rough UI, затем перенос идей (не «сырого» секретосодержащего кода) в локальный Next.js-проект.  
- **Процесс:** brief → промпт с границами MVP → дифф в IDE → ручная проверка валидаций (дата ≥+2 дня, пустая корзина) → commit.  
- **На следующие ДЗ:** зафиксировать стек Next.js + TS + Tailwind и продолжать вести код в том же workspace под контролем Cursor.

### 6.3. Соответствие цели ДЗ1

Выполнены сравнительный анализ не менее четырёх инструментов (3 cloud + 3 IDE/CLI в таблице), обоснованный выбор Cursor, описание настройки и практический пример генерации кода для фрагмента FoodTech-MVP NutriDay.
