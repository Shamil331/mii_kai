# Пользовательские истории NutriDay (ДЗ3)

## Персоны

| Персона | Кратко | Главная мотивация |
|---------|--------|-------------------|
| **Анна, 32** | Офис, мало времени вечером | Быстро выбрать готовый набор на будни |
| **Игорь, 28** | Фрилансер, считает бюджет | Видеть цену и итог до оплаты |
| **Марина, 41** | Работа + семья | Доставка к нужной дате и адресу |

## Пользовательский путь (Happy Path) — этапы для маппинга

1. **Первый вход** — открыть сайт, понять ценность NutriDay  
2. **Онбординг / ориентир** — краткие шаги или сразу каталог  
3. **Выбор типа питания** — фильтр/выбор рациона  
4. **Просмотр меню набора** — состав дня/недели, цена  
5. **Корзина** — количество, итог  
6. **Оформление** — дата (≥+2 дня), адрес, оплата  
7. **Подтверждение** — номер заказа, детали доставки  

*Продукт: responsive web (web + mobile-friendly), не native-only.*

## Истории

### US-01. Просмотр типов питания и меню наборов  
**Приоритет:** Must  
**Этапы пути:** 1, 3, 4  
**Персоны:** Анна, Игорь  

Как **гость/покупатель**, я хочу **видеть типы рационов и меню готовых наборов на день или неделю**, чтобы **понять, подходит ли сервис мне по составу и цене, без сложной настройки**.

**Критерии приёмки (Given–When–Then):**

```gherkin
Given пользователь открыл главную или раздел «Наборы»
When страница загрузилась успешно
Then отображается список доступных типов питания и карточки наборов
  And у каждой карточки видны название, длительность (день/неделя), цена
  And пользователь может открыть детальный просмотр состава набора
```

```gherkin
Given пользователь на экране детального просмотра набора
When он просматривает состав
Then отображаются позиции меню (например, приём пищи / блюда) и цена набора
  And нет элементов глубокой кастомизации блюд
```

### US-02. Добавление набора в корзину  
**Приоритет:** Must  
**Этапы пути:** 4, 5  
**Персоны:** Анна, Марина  

Как **покупатель**, я хочу **добавить выбранный набор в корзину**, чтобы **собрать заказ из готовых наборов**.

**Критерии приёмки:**

```gherkin
Given пользователь находится на карточке или детальной странице набора
When он нажимает «Добавить в корзину»
Then набор появляется в корзине с количеством не меньше 1
  And счётчик/бейдж корзины обновляется
  And пользователь получает понятное подтверждение действия (тост или переход)
```

```gherkin
Given тот же набор уже есть в корзине
When пользователь снова нажимает «Добавить в корзину»
Then количество этой позиции увеличивается на 1
  And итоговая сумма корзины пересчитывается
```

### US-03. Изменение количества в корзине  
**Приоритет:** Must  
**Этапы пути:** 5  
**Персоны:** Игорь  

Как **покупатель**, я хочу **просматривать состав корзины и изменять количество наборов**, чтобы **скорректировать заказ и бюджет до оплаты**.

**Критерии приёмки:**

```gherkin
Given в корзине есть хотя бы одна позиция
When пользователь открывает корзину
Then отображается список позиций с названием, ценой за единицу, количеством и суммой по позиции
  And под списком видна итоговая сумма заказа
```

```gherkin
Given корзина открыта
When пользователь нажимает «+» или «−» у позиции
Then количество обновляется
  And сумма позиции и итог заказа пересчитываются автоматически
```

```gherkin
Given у позиции количество равно 1
When пользователь нажимает «−»
Then позиция удаляется из корзины
  And итог пересчитывается без этой позиции
```

### US-04. Выбор даты доставки и адреса  
**Приоритет:** Must  
**Этапы пути:** 6  
**Персоны:** Марина  

Как **покупатель**, я хочу **указать дату доставки и адрес**, чтобы **получить наборы в удобное время с учётом срока производства**.

**Критерии приёмки:**

```gherkin
Given в корзине есть позиции и пользователь перешёл к оформлению
When открывается шаг выбора даты доставки
Then недоступны даты раньше чем «сегодня + 2 календарных дня»
  And пользователь может выбрать одну доступную дату
```

```gherkin
Given дата доставки выбрана
When пользователь вводит адрес доставки и подтверждает шаг
Then адрес сохраняется в черновике заказа
  And без валидного адреса переход к оплате блокируется с понятным сообщением
```

---

### US-05. Оплата и подтверждение заказа  
**Приоритет:** Must  
**Этапы пути:** 6, 7  
**Персоны:** Анна, Игорь, Марина  

Как **покупатель**, я хочу **оплатить заказ и увидеть подтверждение**, чтобы **быть уверенным, что заказ принят и доставка запланирована**.

**Критерии приёмки:**

```gherkin
Given заполнены дата доставки и адрес, корзина не пуста
When пользователь инициирует оплату и платёж успешен
Then создаётся заказ со статусом «оплачен» / «подтверждён»
  And отображается экран подтверждения с идентификатором заказа, датой доставки, адресом и суммой
  And корзина очищается от оплаченных позиций
```

```gherkin
Given пользователь на шаге оплаты
When платёж отклонён или отменён
Then заказ не считается оплаченным
  And пользователь видит сообщение об ошибке и может повторить оплату или вернуться к данным заказа
```

### US-06. Краткий онбординг ценности сервиса  
**Приоритет:** Should  
**Этапы пути:** 1, 2  
**Персоны:** Анна (первый визит)  

Как **новый посетитель**, я хочу **за 1 экран понять, как работает NutriDay**, чтобы **решить, стоит ли выбирать набор**.

**Критерии приёмки:**

```gherkin
Given пользователь открыл сайт впервые (или без сохранённого флага «онбординг пройден»)
When отображается онбординг или hero-блок
Then показаны кратко: выбор рациона → набор день/неделя → оплата и доставка с правилом «+2 дня»
  And есть CTA перехода к каталогу наборов
  And пользователь может пропустить блок и сразу открыть меню
```

### US-07. Пустая корзина и повторный переход в меню  
**Приоритет:** Nice  
**Этапы пути:** 5, 3  
**Персоны:** Игорь  

Как **покупатель**, я хочу **видеть понятное состояние пустой корзины**, чтобы **быстро вернуться к выбору наборов**.

**Критерии приёмки:**

```gherkin
Given корзина не содержит позиций
When пользователь открывает корзину
Then отображается пустое состояние с пояснением и кнопкой «К наборам»
  And CTA оформления заказа недоступен
```
